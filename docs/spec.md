# 사이드바 브라우저 구현 명세

Nov 10, 2026 · @연우

## 1. 개요와 범위

Windows용 개인 웹 브라우저를 만든다. 탭과 북마크는 왼쪽 사이드바에 있고, 웹 페이지는 WebView2(Edge와 같은 크로미움 엔진)가 그린다.

- **사용자**: 만드는 사람 본인과 지인 한두 명. 공개 배포는 목표가 아니다.
- **플랫폼**: Windows 10/11 x64만 지원한다.
- **이름**: TB's Browser. 파일·폴더 이름처럼 아포스트로피를 쓸 수 없는 곳에는 TBs Browser를 쓴다. 코드에서는 `APP_NAME` 상수 하나로 관리해 나중에 한 곳만 바꾸면 되게 한다.

목표는 네 가지다.

1. 시안대로의 무채색 미니멀 UI (4장)
2. Edge와 같은 수준의 사이트 호환성
3. 백그라운드 탭 관리로 메모리 절약 (7장)
4. 사이트별 스크립트와 크롬 확장, 내장 광고 차단으로 필요한 기능 추가 (6장)

하지 않는 것은 다음과 같다.

- 자체 웹 렌더링 엔진, 크로미움 포크, 파이어폭스 포크
- 크롬 웹 스토어 설치 흐름, 계정 동기화
- macOS, Linux, 모바일
- 스페이스(업무/개인 전환), 탭 나이에 따른 명도 변화, 바탕 질감. 디자인 과정에서 뺀 기능이라 다시 넣지 않는다.

## 2. 결정 사항

아래 표의 항목은 이미 정했다. 다르게 구현해야 할 이유가 생기면 먼저 사용자에게 묻는다.

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 웹 렌더링 | WebView2 (자동 업데이트되는 Evergreen 런타임) | Edge와 같은 호환성. 엔진 보안 패치를 직접 관리하지 않는다 |
| 호스트 언어 | Rust | 가벼운 껍데기, 탭·메모리 정책을 직접 제어 |
| 앱 틀 | Tauri 2 + `unstable` 기능(한 창에 여러 웹뷰). 0단계에서 확정. 버전 고정: tauri 2.12.5, tauri-build 2.7.4, webview2-com 0.39.1, windows 0.62.2 | 시안이 HTML/CSS라 가장 빨리 옮길 수 있다 |
| 브라우저 UI | Svelte 5 + TypeScript + Vite로 만든 UI 웹뷰 하나 | 그림자, 둥근 모서리 같은 시안 디테일을 그대로 쓴다. Svelte는 가상 DOM 런타임이 없어 번들이 작고 시작이 가볍다 |
| 확장 기능 | 내장 "사이트 스크립트"가 기본. 압축 해제 확장 불러오기는 보조 | 필요한 확장은 직접 만들어 쓴다. 확장 형식을 맞출 필요가 없다 |
| 메모리 | 백그라운드 탭 재우기·버리기 정책 | 탭 하나의 메모리는 크로미움과 같다. 줄일 수 있는 곳은 정책뿐이다 |
| 색 | 무채색. 창 바탕에만 그라디언트, 요소 안쪽은 단색 | 디자인 검토에서 확정 |
| 주소창 | 페이지 위 상단 툴바, 페이지 카드 중심선에 정렬 | 디자인 검토에서 확정 |
| 북마크 | 폴더가 있는 목록. 탭과 한 영역에서 같이 스크롤, 머리줄로 접기 | 개수가 늘어도 확장하기 쉽다 |
| 새 탭 | "새 탭" 줄은 탭 목록 위. 새로 연 탭은 목록 맨 위에 쌓임 | 방금 연 탭이 스크롤 없이 보인다 |
| 사이드바 하단 | 확장 프로그램 버튼과 세로 점 3개 메뉴(다운로드, 방문 기록, 설정) | 디자인 검토에서 확정 |
| 창 버튼 | Windows식 최소화·최대화·닫기를 오른쪽 위에 | 사용 환경이 Windows |

추가로 정한 것은 다음과 같다.

| 항목 | 결정 |
| --- | --- |
| 이름 | 화면에 보이는 이름은 TB's Browser. 파일·폴더·식별자에는 TBs Browser |
| 기본 테마 | 라이트. 설정에서 다크와 시스템 따름으로 바꿀 수 있다 |
| 기본 검색 엔진 | Google. 설정에서 바꿀 수 있다 |
| 전달 방식 | 설치 파일과 자동 업데이트 (5.7) |

아직 정하지 않은 것은 다음과 같다. 괄호 안은 정해지기 전까지 쓸 가정이다.

- 업데이트 파일을 올릴 곳 (GitHub Releases)
- 앱 식별자 (`com.tbsbrowser.app`)

## 3. 아키텍처

프로그램은 Rust 호스트 하나이고, 창 안에 UI 웹뷰 하나와 탭마다 콘텐츠 웹뷰 하나를 둔다. 모든 웹뷰는 WebView2 환경 하나와 사용자 데이터 폴더 하나를 같이 쓴다.

| 구성 요소 | 기술 | 맡는 일 |
| --- | --- | --- |
| 호스트 | Rust (Tauri 2) | 창, 탭 수명 관리, 웹뷰 배치, 저장, 사이트 스크립트 주입, 메모리 정책, 다운로드 |
| UI 웹뷰 | HTML/CSS/TypeScript | 사이드바, 상단 툴바, 메뉴. 창 전체를 덮는다 |
| 콘텐츠 웹뷰 | WebView2, 탭당 하나 | 웹 페이지. 페이지 카드 자리에 놓이고, 활성 탭만 보인다 |
| 내부 페이지 | UI와 같은 번들 | 새 탭 화면, 설정, 방문 기록, 다운로드 목록. UI 웹뷰가 페이지 카드 자리에 직접 그리고, 콘텐츠 웹뷰는 만들지 않는다 |

### 배치

- 창은 기본 제목 표시줄이 없는 창이다. 최소화·최대화·닫기 버튼과 창 드래그 영역은 UI 웹뷰가 그린다.
- UI 웹뷰는 창 전체 크기다. 콘텐츠 웹뷰는 그 위에, 페이지 카드 사각형 자리에 놓는다.
- 카드 사각형의 좌표는 UI가 계산해 호스트에 알린다. 창 크기가 바뀌거나 사이드바를 접고 폼 때마다 다시 알린다.
- 모든 웹뷰는 `with_environment`로 WebView2 환경 객체 하나를 넘겨받아 만든다. 넘기지 않으면 Tauri가 웹뷰마다 환경을 따로 만든다.
- 페이지 카드의 둥근 모서리는 콘텐츠 웹뷰의 창 영역을 잘라내는 방식(`SetWindowRgn`)으로 만든다. 가장자리가 매끄럽지 않아 어두운 페이지에서 계단이 보일 수 있다. 설정 하나로 각진 모서리로 바꿀 수 있게 한다. 비주얼 호스팅은 쓰지 않는다.
- 콘텐츠 위에 뜨는 팝업(주소창 자동완성, 메뉴, 접힌 상태의 북마크 목록)은 메인 창이 소유한 투명 팝업 창으로 띄운다. 포커스를 가져가지 않게 띄우고(`WS_EX_NOACTIVATE`, `SW_SHOWNOACTIVATE`), 메인 창을 옮기거나 크기를 바꾸기 시작하면 닫는다.
- 창 틀에는 우회 두 가지가 필요하다. 위쪽 변 크기 조절은 웹뷰를 다 만든 뒤 `set_decorations`를 켰다 끄면 된다. 스냅 레이아웃은 최대화 버튼 자리에 `HTMAXBUTTON`을 돌려주는 자식 창을 둔다.

### 통신

- **상태의 원본은 호스트가 갖는다.** 탭 목록, 북마크, 설정은 호스트에 있고 UI는 받아서 그리기만 한다.
- **UI → 호스트**: 명령 호출. 예: `tab_create`, `tab_close`, `tab_activate`, `navigate`, `go_back`, `bookmark_add`, `set_content_bounds`.
- **호스트 → UI**: 이벤트. 예: `tabs_changed`, `tab_updated`(제목, 파비콘, 주소, 로딩, 소리 재생), `download_progress`.
- **콘텐츠 웹뷰 → 호스트**: WebView2 이벤트(이동, 제목 변경, 새 창 요청, 다운로드 등)와 사이트 스크립트의 메시지(6장).

### 보안 경계

콘텐츠 웹뷰에는 앱 명령을 노출하지 않는다. 원격 웹 페이지가 탭을 닫거나 파일을 저장하는 명령을 부를 수 있으면 안 된다. 0단계에서 확인한 방법은 다음 세 가지를 함께 쓰는 것이다.

- `build.rs`의 `AppManifest::commands`로 앱 명령에 권한을 건다.
- capability를 `"webviews": ["ui"]`로 범위 지정해 UI 웹뷰에만 허용한다.
- 콘텐츠 웹뷰는 `on_navigation`으로 앱 내부 주소로 이동하지 못하게 막는다.

내부 페이지(새 탭 화면, 설정 등)는 앱 명령이 필요하므로 콘텐츠 웹뷰가 아니라 UI 웹뷰가 그린다. 콘텐츠 페이지에서도 `__TAURI_INTERNALS__` 객체는 보인다. 명령 호출은 거부되지만, `withGlobalTauri`를 끈 뒤 무엇이 남는지는 아직 확인하지 않았다(10장).

### 0단계에서 확인한 것

0단계에서 이 구조로 진행할 수 있음을 확인했다. 13개 항목 중 12개가 됐고, 리소스 바꿔치기 하나만 대안이 필요했다(6.2).

- 앱 틀은 Tauri 2 + `unstable` 그대로 간다. `wry`·`tao` 직접 사용이나 `webview2-com` 직접 제어로 바꾸지 않는다.
- 네이티브 WebView2 API는 `with_webview`로 얻은 컨트롤러와 환경을 통해 부른다.
- 단축키는 `AcceleratorKeyPressed`로 받고 `SetHandled`로 페이지에 전달되지 않게 한다.
- 비밀번호 저장과 자동 입력은 WebView2 설정의 `IsPasswordAutosaveEnabled`, `IsGeneralAutofillEnabled`로 켠다.
- DRM은 Widevine과 PlayReady를 지원한다. 보호된 영상은 화면 캡처에 검게 찍힌다.

시험 환경은 Windows 11, 화면 배율 100%, WebView2 런타임 157이다. 항목별 상세 결과는 `docs/S0-results.md`에 있다.

## 4. 화면 설계

화면은 시안 다섯 장을 그대로 구현한다. 시안 원본은 [사이드바 웹 브라우저 시안](https://claude.ai/artifact/1pbzBaCaV6js6vQoUhsNan) 캔버스에 있고, 시안 HTML 파일을 저장소의 `design/` 폴더에 넣어 값의 기준으로 쓴다.

| 시안 | 파일 | 내용 |
| --- | --- | --- |
| F · 미니멀 | `Main.dc.html` | 기본 화면, 라이트 |
| G · 미니멀 (다크) | `G-MinimalDark.dc.html` | 기본 화면, 다크 |
| H · 미니멀 (접힘) | `H-MinimalCollapsed.dc.html` | 사이드바를 접은 상태, 라이트 |
| I · 새 탭 화면 | `I-NewTab.dc.html` | 새 탭 화면, 라이트 |
| J · 새 탭 화면 (다크) | `J-NewTabDark.dc.html` | 새 탭 화면, 다크 |

접힌 상태의 다크 시안은 없다. G의 색을 H의 구조에 적용한다.

9~12단계(6.6~6.9)에 새로 생기는 화면의 시안은 `docs/design-request-S9.md`로 요청해 2026-11-11에 받았다. 시안을 만든 쪽의 결정과 새 값은 `design/S9-notes.md`에 있다.

| 시안 | 파일 | 내용 |
| --- | --- | --- |
| K · 확장 패널 | `K-ExtensionsPanel.dc.html` | 확장 패널, 항목 상태, 고정 아이콘, 접힌 상태 (라이트만) |
| L · 광고 차단 | `L-AdBlock.dc.html`, `L-AdBlockDark.dc.html` | 주소창 방패 버튼, 광고 차단 팝업, 설정 페이지 구역 |
| M · 설치·권한 확인 | `M-InstallConfirm.dc.html` | 설치, 업데이트, "모든 사이트" 켜기 확인 (라이트만) |
| N · 스크립트 설정 | `N-ScriptSettings.dc.html`, `N-ScriptSettingsDark.dc.html` | 설정 칸으로 그리는 화면 (마우스 제스처, 유튜브 차단 예시) |
| O · 찾아보기 | `O-ScriptStore.dc.html`, `O-ScriptStoreDark.dc.html` | 스크립트 저장소 목록, 빈 상태, 오류 상태 |
| P · 페이지 안 | `P-InPage.dc.html` | 제스처 궤적과 꼬리표, PiP 버튼 |

K와 M은 다크 시안이 없다. 기존 토큰만 쓰므로 G의 색을 그대로 적용한다.

시안에서 정한 것 중 동작에 관한 것은 다음과 같다.

- 고정 아이콘은 4개까지 보인다. 5개째부터 확장 버튼이 `+N`으로 바뀐다. 접힌 사이드바에서는 고정 아이콘이 보이지 않는다.
- 확장 패널의 항목은 켜기·끄기만 늘 보인다. 설정·고정·지우기와 "이 탭에서 실행"·팝업 열기·업데이트는 줄을 눌러 펼쳤을 때 보인다.
- 방패 버튼에는 숫자를 넣지 않는다. 막은 개수는 팝업에 크게 보인다. 이 개수는 지금 페이지에서 막은 요청 수이고, 새로 불러오면 0부터 다시 센다. 내부 페이지와 새 탭에서는 방패를 숨긴다.
- 설치·권한 확인은 주소창 아래 가운데에 붙는 페이지 위 팝업 창이다. 바깥을 눌러도 닫히지 않고 "취소"나 Esc로만 닫는다. 페이지 안에 그리지 않으므로 사이트가 흉내 낼 수 없다.

### 4.1 화면 구조

```
+----------------------+------------------------------------------------------+
| [접기] [ 탭 검색     ] | [<] [>] [새로고침]     [ 주소창        별 ]   [다운로드] [-][□][x] |
+----------------------+------------------------------------------------------+
| 북마크 v            + |                                                      |
|   (북마크 목록)        |                                                      |
| -------------------- |                                                      |
| 탭                   |              페이지 카드 (웹 페이지)                    |
| + 새 탭              |                                                      |
|   (탭 목록)           |                                                      |
| -------------------- |                                                      |
| [고정][고정][확장]  [⋮] |                                                      |
+----------------------+------------------------------------------------------+
```

- 왼쪽 열이 사이드바, 오른쪽 열이 상단 툴바와 페이지 카드다.
- 사이드바에서 고정된 것은 맨 위 줄(접기 버튼, 탭 검색)과 맨 아래 줄(확장, 메뉴)이다. 그 사이는 하나의 스크롤 영역이다.

| 메뉴 팝업 | 폭 200px, 모서리 10px, 항목 높이 32px |
| 페이지 카드 | 모서리 12px |
| 접힌 상태 버튼 | 36×34px, 모서리 8px |

글꼴은 Inter와 Noto Sans KR, 기본 글자 크기는 13px이다. 아이콘은 선 두께 1.8px의 선 아이콘 한 세트를 쓴다.

### 4.4 상단 툴바

- 왼쪽부터 뒤로, 앞으로, 새로고침, 주소창, 다운로드 표시, 창 버튼 순서다.
- 주소창은 페이지 카드의 중심선에 맞춘다. 주소창 왼쪽 묶음과 오른쪽 묶음에 같은 폭을 주는 방식이다.
- 주소창 안에는 왼쪽에 자물쇠 아이콘, 오른쪽 끝에 북마크 추가(별) 버튼이 있다.
- 다운로드 표시는 다운로드가 진행 중일 때만 나타난다. 진행률을 둥근 고리로 보여준다.
- 툴바의 빈 공간은 창을 끌어 옮기는 영역이다.

### 4.5 사이드바

- **맨 위 줄**: 사이드바 접기 버튼과 탭 검색 칸.
- **북마크 구역**: 머리줄(접기 화살표, "북마크", 추가 버튼)과 목록. 폴더는 펼치고 접을 수 있고, 머리줄을 누르면 구역 전체가 접힌다.
- **탭 구역**: "탭" 제목, "새 탭" 줄, 탭 목록. "새 탭" 줄은 다른 탭과 같은 진하기의 평범한 줄이다.
- **스크롤**: 북마크와 탭이 한 영역에서 같이 스크롤된다. 북마크가 위로 지나가면 "탭" 제목과 "새 탭" 줄이 영역 맨 위에 붙고, 그 아래에 얇은 선이 생긴다.
- **탭 줄**: 파비콘, 제목(넘치면 말줄임). 선택된 탭은 단색 면과 그림자로 구분하고 닫기 버튼이 보인다. 다른 탭은 마우스를 올렸을 때 닫기 버튼이 보인다.
- **탭 상태**: 불러오는 중이면 파비콘 자리에 회전하는 고리, 소리가 나면 제목 오른쪽에 재생 표시.
- **탭 그룹**: 그룹 이름 줄(화살표 + 이름) 아래에 들여 쓴 탭들. 스크롤 중 그 그룹을 지나는 동안 그룹 이름 줄이 위에 붙는다.
- **맨 아래 줄**: 왼쪽에 고정한 사이트 스크립트 아이콘들과 확장 프로그램 버튼, 오른쪽 끝에 세로 점 3개 버튼. 점 3개를 누르면 다운로드·방문 기록·설정 메뉴가 위로 펼쳐진다. 이 줄 위에 얇은 구분선이 있다.

### 4.6 접힌 상태

- 사이드바가 44px 폭의 아이콘 한 줄이 된다.
- 위에서부터 펼치기, 탭 검색, 북마크(버튼 하나, 누르면 목록이 뜬다), 구분선, 새 탭, 탭 파비콘들 순서다. 맨 아래에 확장 프로그램과 점 3개 버튼이 있다.
- 탭 그룹은 옵은 둥근 바탕(라이트 `rgba(0,0,0,.07)`, 모서리 10px) 하나로 묶어 보여준다.
- 탭 파비콘 목록만 스크롤되고 스크롤 막대는 보이지 않는다.
- 고정한 사이트 스크립트 아이콘은 접힌 상태에서 확장 프로그램 버튼 안으로 들어간다.

### 4.7 새 탭 화면

- 페이지 카드 가운데(살짝 위)에 검색·주소 입력 칸과 "자주 가는 곳" 바로가기만 둔다.
- 검색 칸은 높이 52px, 모서리 26px, 글자 15px이다. 최대 폭은 640px로 위쪽 주소창과 좌우 끝이 같다.
- 바로가기는 4×2 격자(최대 폭 440px, 간격 8px)이다. 각 칸은 44px 아이콘 바탕(모서리 12px)과 12px 이름이다.
- 새 탭 화면에서 위쪽 주소창은 비어 있고 "검색어 또는 주소 입력" 안내 문구를 보여준다.
- 다크 테마에서는 페이지 카드도 어둡게 그린다.

## 5. 기능 명세

매일 쓰는 브라우저에 필요한 기본 기능을 영역별로 정리한다. 표에 없는 기능은 만들지 않는다.

### 5.1 탭

| 동작 | 규칙 |
| --- | --- |
| 새 탭 | 목록 맨 위에 추가하고 새 탭 화면을 띄운다. 검색 칸에 포커스를 준다 |
| 닫기 | 선택된 탭을 닫으면 바로 아래 탭을 선택한다. 아래가 없으면 위 탭. 마지막 탭을 닫으면 새 탭 하나를 연다 |
| 링크를 새 탭으로 | 페이지가 새 창을 요청하거나 가운데 클릭하면 현재 탭 바로 위에 새 탭으로 연다 |
| 순서 바꾸기 | 드래그로 위아래 이동. 그룹 안팔으로도 옮길 수 있다 |
| 그룹 | 만들기, 이름 바꾸기, 접기, 풀기 |
| 탭 검색 | 입력하는 동안 제목과 주소에 그 글자가 들어간 탭만 남긴다. 지우면 전체 목록으로 돌아온다 |
| 닫은 탭 되살리기 | 최근 닫은 탭 20개를 기억하고 역순으로 되살린다 |
| 자동 스크롤 | 탭을 바꾸면 그 탭이 보이도록 목록이 따라간다 |

### 5.2 주소창과 이동

- 입력이 주소 모양이면(점이 있고 공백이 없거나 `http`로 시작) 그 주소로 간다. 아니면 기본 검색 엔진으로 검색한다.
- 입력 중에는 방문 기록과 북마크에서 최대 6개를 자동완성으로 보여준다.
- 평소에는 `https://`를 뺀 주소를 보여주고, 클릭하면 전체 주소를 선택한 상태로 바꾼다.
- 자물쇠 아이콘은 HTTPS일 때만 보인다.
- 별 버튼은 현재 페이지를 북마크에 넣거나 뺀다. 이미 북마크된 페이지면 채워진 별로 보인다.
- 뒤로·앞으로 버튼은 갈 곳이 없으면 옵게 보이고 눌리지 않는다. 로딩 중에는 새로고침 버튼이 중지 버튼으로 바뀐다.

### 5.3 북마크

- 구조는 폴더를 겹칠 수 있는 트리다.
- 추가는 주소창의 별 버튼, 북마크 머리줄의 추가 버튼, 탭을 북마크 구역으로 끌어놓기 세 가지로 한다.
- 클릭하면 현재 탭에서 열고, Ctrl+클릭이나 가운데 클릭은 새 탭으로 연다.
- 오른쪽 클릭 메뉴로 이름 바꾸기, 삭제, 새 폴더를 한다. 드래그로 순서와 폴더를 바꾼다.
- 폴더와 구역 전체의 접힘 상태를 기억한다.

### 5.4 다운로드, 방문 기록, 설정, 세션

| 영역 | 동작 |
| --- | --- |
| 다운로드 | 진행 중일 때만 툴바에 진행 고리가 나타난다. 누르면 진행 중인 항목이 뜨고, 전체 목록은 점 3개 메뉴의 "다운로드"에서 연다. 항목마다 파일 열기, 폴더 열기, 취소가 있다 |
| 방문 기록 | 이동이 끝난 페이지의 주소·제목·시각을 저장한다. 기록 페이지에서 검색, 개별 삭제, 전체 삭제를 한다 |
| 설정 | 테마(라이트·다크·시스템 따름, 기본값 라이트), 기본 검색 엔진(기본값 Google), 다운로드 폴더, 시작할 때 이전 탭 복원 여부, 메모리 정책 값(7장), 사이트 스크립트 관리(6장) |
| 세션 | 탭·그룹·선택된 탭·사이드바 상태를 바뀔 때마다 저장한다. 시작할 때 복원하되, 선택된 탭만 로드하고 나머지는 누를 때 로드한다 |

### 5.5 웹 페이지가 요구하는 동작

- **전체 화면**: 영상이 전체 화면을 요청하면 사이드바와 툴바를 숨기고 콘텐츠를 창 전체로 키운다.
- **권한 요청**: 카메라, 마이크, 알림, 위치 요청이 오면 허용·차단을 묻고 사이트별로 기억한다.
- **페이지 안 찾기, 인쇄, 확대·축소, 오른쪽 클릭 메뉴, 개발자 도구**: WebView2가 기본 제공하는 것을 그대로 쓴다.
- **비밀번호 저장과 자동 입력**: WebView2 설정으로 켤 수 있는지 0단계에서 확인하고, 되면 켠다.

### 5.7 설치와 업데이트

- **설치 파일**: Tauri의 NSIS 설치 파일(`-setup.exe`) 하나로 전달한다. MSI는 만들지 않는다.
- **WebView2 런타임**: 런타임이 없는 PC에서는 설치 파일이 내려받아 설치한다(`webviewInstallMode`의 `downloadBootstrapper` 또는 `embedBootstrapper`).
- **업데이트 확인**: Tauri updater 플러그인을 쓴다. 시작할 때와 그 뒤 하루에 한 번 새 버전을 확인한다.
- **업데이트 설치**: 새 버전이 있으면 점 3개 버튼에 작은 점을 표시하고 메뉴에 "업데이트 설치" 항목을 보여준다. 사용자가 누르면 내려받아 설치하고 다시 시작한다. 묻지 않고 재시작하지 않는다. 재시작 뒤에는 세션 복원으로 탭이 돌아온다.
- **서명**: 업데이트 파일은 updater 서명 키로 서명한다. 공개 키는 설정에 넣고, 개인 키는 저장소 밖에 보관한다.
- **올리는 곳**: 버전 정보를 담은 정적 JSON 파일(`latest.json`)과 설치 파일을 같은 곳에 올린다. 장소는 2장의 미정 항목이다.
- **Windows 경고**: 코드 서명 인증서가 없으므로 처음 설치할 때 Windows SmartScreen 경고가 뜰 수 있다. 지인에게 전달할 때 미리 알린다.

## 6. 사이트 스크립트

확장 프로그램 대신, 사이트별로 스크립트와 스타일을 끼워 넣는 기능을 브라우저에 내장한다. 사이드바의 확장 프로그램 버튼이 이 기능의 관리 화면을 연다.

### 6.1 스크립트 하나의 구조

스크립트는 `scripts/<id>/` 폴더 하나다. 설정 파일 `script.json`과 스크립트·스타일·이미지 파일이 들어간다.

```json
{
  "id": "chess-pieces",
  "name": "체스닷컴 기물 바꾸기",
  "matches": ["https://www.chess.com/*"],
  "run_at": "document_end",
  "js": ["main.js"],
  "css": ["style.css"],
  "resource_overrides": [
    { "pattern": "https://images.chesscomfiles.com/*/wp.png", "file": "pieces/wp.png" }
  ],
  "permissions": [],
  "enabled": true,
  "pinned": false
}
```

| 항목 | 뜻 |
| --- | --- |
| `matches` | 적용할 주소 패턴 목록. `*`는 아무 글자나 |
| `run_at` | `document_start`(페이지 스크립트보다 먼저) 또는 `document_end`(문서 구조가 준비된 뒤) |
| `js`, `css` | 끼워 넣을 파일. 적힌 순서대로 넣는다 |
| `resource_overrides` | 페이지가 요청하는 파일을 폴더 안 파일로 바꿔치기 |
| `permissions` | 브라우저에 부탁할 수 있는 일 (6.3) |
| `enabled`, `pinned` | 켜짐 여부, 사이드바 맨 아래 줄에 아이콘을 고정할지 |
| `icon` | 아이콘 파일(폴더 안의 PNG나 SVG). 없으면 이름 첫 글자로 그린다 (6.4) |
| `version`, `description`, `author` | 스크립트 저장소(6.8)와 관리 화면에 보이는 정보 |
| `settings` | 설정 칸 목록. 관리 화면이 설정 화면을 그린다. 칸 종류는 켜기, 숫자, 글자, 글자 목록, 고르기 |
| `shortcuts` | 단축키와 이름. 페이지에 포커스가 있어도 스크립트에 전달된다 |
| `actions` | 확장 패널에 보일 "이 탭에서 실행" 버튼과 이름 |

`matches`에 `*`(모든 사이트)를 쓰는 스크립트는 켤 때 "모든 사이트에서 실행된다"고 알리고 묻는다.

예시의 주소 패턴과 파일 이름은 형식을 보이기 위한 것이다. 실제 값은 스크립트를 만들 때 해당 사이트를 보고 정한다.

### 6.2 동작 방식

1. **주입**: 콘텐츠 웹뷰를 만들 때, 켜진 스크립트마다 WebView2의 `AddScriptToExecuteOnDocumentCreated`로 등록한다. 등록하는 코드는 "현재 주소가 `matches`에 맞을 때만 실행"하도록 감싼다.
2. **스타일**: CSS는 스크립트가 `<style>` 요소를 만들어 넣는다.
3. **실행 시점**: `document_end`는 문서 준비 이벤트를 기다렸다가 실행한다.
4. **바꾸면 다시 등록**: 스크립트를 켜거나 끄거나 파일을 고치면 기존 등록을 지우고 다시 등록한다. 열려 있는 탭은 새로고침 뒤에 반영된다.
5. **리소스 바꿔치기**: `AddWebResourceRequestedFilter`로 패턴을 걸고, `WebResourceRequested` 이벤트에서 폴더 안 파일로 응답을 만들어 돌려준다. 필터는 필요한 패턴에만 건다.

리소스 바꿔치기에는 0단계에서 확인한 한계가 두 가지 있다.

- **캐시**: 새로 요청되는 파일에만 적용된다. 캐시에 있는 파일은 가로채지 못한다. 리소스 바꿔치기가 있는 스크립트를 켜거나 고칠 때 디스크 캐시를 비운다. 이때 프로필 전체의 캐시가 비워진다.
- **서비스 워커**: 서비스 워커를 거치는 요청은 가로채지 못한다. 그런 사이트에서는 스타일 덮어쓰기를 쓴다.

따라서 이미지를 바꾸는 스크립트는 스타일 덮어쓰기를 먼저 쓰고, 그것으로 안 될 때만 리소스 바꿔치기를 쓴다.

유튜브처럼 페이지를 새로 불러오지 않고 화면만 바꾸는 사이트가 있다. 이런 곳에서는 스크립트가 화면 변화를 지켜보다가 버튼을 다시 달아야 한다. 이것은 각 스크립트의 몫이다.

### 6.3 브라우저에 부탁하는 일

스크립트는 페이지 안에서만 돈다. 파일 저장처럼 페이지 밖의 일은 호스트에 메시지를 보내 부탁한다.

| 부탁 | 호스트가 하는 일 |
| --- | --- |
| `screenshot` | 현재 탭 화면을 PNG로 찍어 다운로드 폴더에 저장한다. DRM으로 보호된 영상은 검게 찍힌다 |
| `saveFile` | 스크립트가 준 데이터를 다운로드 폴더에 저장한다. 파일 이름에서 경로 글자를 제거한다 |
| `copyText` | 글자를 클립보드에 넣는다 |
| `tabs` | 메시지가 온 그 탭에서만: 뒤로·앞으로, 새로고침, 탭 닫기, 새 탭, 닫은 탭 되살리기, 위·아래 탭으로 가기. 다른 탭의 주소나 내용은 읽을 수 없다 |
| `storage` | 스크립트별 저장 공간 `scripts\<id>\storage.json`(최대 5MB)에 값을 읽고 쓴다 |

설치 확인 창(시안 M)에 보이는 권한 문장은 다음과 같다.

| 권한 | 문장 |
| --- | --- |
| `screenshot` | 이 탭 화면을 찍어 다운로드 폴더에 저장함 |
| `saveFile` | 파일을 다운로드 폴더에 저장함 |
| `copyText` | 클립보드에 글자를 넣음 |
| `tabs` | 이 탭을 닫거나 뒤로 가게 하고, 새 탭을 열 수 있음 |
| `storage` | 자기 설정을 저장함 |
| 크롬 확장의 `<all_urls>`, `*://*/*` 같은 사이트 권한 | 모든 사이트의 내용을 읽고 바꿀 수 있음 (사이트가 정해져 있으면 그 사이트 칩으로 보인다) |
| 크롬 확장의 `storage`, `unlimitedStorage` | 자기 설정을 저장함 |
| 크롬 확장의 `alarms` | 정해진 시각에 스스로 일을 할 수 있음 |
| 크롬 확장의 `contextMenus` | 오른쪽 클릭 메뉴에 항목을 더함 |
| 크롬 확장의 `declarativeNetRequest…` | 네트워크 요청을 막거나 바꿈 (이 브라우저에서는 동작하지 않음) |
| 크롬 확장의 `tabs` | 열린 탭의 주소와 제목을 읽음 |
| 크롬 확장의 `notifications` | 알림을 띄움 |
| 크롬 확장의 그 밖의 권한 | 권한 이름을 그대로 보인다 |

`settings`의 값은 권한 없이 읽을 수 있다. 새 권한(`tabs`, `storage`)이 있는 스크립트는 켜거나 설치할 때 권한 목록을 보여 주고 묻는다.

보안 규칙은 세 가지다.

- 끼워 넣은 스크립트는 페이지 자체의 스크립트와 같은 공간에서 돈다. 따라서 페이지도 같은 메시지를 보낼 수 있다고 보고, 모든 메시지를 의심한다.
- 메시지를 보낸 페이지의 주소가, 그 권한을 가진 켜진 스크립트의 `matches`에 맞을 때만 처리한다.
- 부탁할 수 있는 일은 위 표가 전부다. 임의 경로 쓰기, 파일 읽기, 프로그램 실행은 만들지 않는다.

### 6.4 관리 화면

- 확장 프로그램 버튼을 누르면 확장 패널이 뜬다. 사이트 스크립트와 크롬 확장(6.6)이 한 목록에 있다. 항목마다 아이콘, 이름, 적용 사이트, 켜고 끄기, 고정이 있고, 해당하면 설정·팝업·"이 탭에서 실행" 버튼이 있다.
- 아이콘은 파비콘처럼 각자 정한다. 사이트 스크립트는 `script.json`의 `icon`, 크롬 확장은 `manifest.json`의 `icons`(또는 `action.default_icon`)를 쓴다. 없는 것만 지금처럼 이름 첫 글자로 그린다. 사이드바 맨 아래 줄의 고정 아이콘도 같다.
- "스크립트 폴더 열기"와 "다시 불러오기" 버튼을 둔다. 폴더에 새 스크립트를 넣고 다시 불러오면 목록에 나타난다.
- 현재 탭에 적용 중인 스크립트를 목록 맨 위에 모아 보여준다.

### 6.5 완성 기준이 되는 두 스크립트

이 두 개가 동작하면 기능이 완성된 것으로 본다.

1. **체스닷컴 기물 이미지 바꾸기**: 기물 이미지가 폴더에 넣은 이미지로 보인다. 스타일 덮어쓰기와 리소스 바꿔치기 중 되는 방법을 쓴다.
2. **유튜브 스크린샷 버튼**: 플레이어 아래에 버튼이 생기고, 누르면 현재 영상 화면이 PNG로 저장된다. 다른 영상으로 넘어가도 버튼이 유지된다.

### 6.6 크롬 확장

기존 크롬 확장(MV3)을 그대로 쓴다. 2026-11-11 시험(`docs/extensions-plan.md` 1장)에서 콘텐츠 스크립트, 서비스 워커, `storage`·`alarms`, 확장 페이지는 동작했다. 네트워크 차단 규칙(`declarativeNetRequest`)은 API는 있지만 실제로 막지 않았다.

- **설치**: 압축을 푼 폴더나 `.zip`을 고른다. `extensions\<id>\`에 복사해 두고, 시작할 때마다 프로필의 `AddBrowserExtension`으로 등록한다.
- **켜기·끄기·지우기**: WebView2 확장 객체의 `Enable`, `Remove`로 한다. 지울 때는 확장의 저장 데이터도 지워진다고 알리고 묻는다.
- **확장 허용**: 모든 웹뷰(UI, 팝업, 콘텐츠)를 만들 때 확장 허용을 켠다. 환경 옵션이 모두 같아야 한다(0단계 13번).
- **아이콘과 팝업**: WebView2는 확장 아이콘과 팝업을 그리지 않는다. 확장 패널과 고정 아이콘을 누르면 `action.default_popup`을 콘텐츠 위 팝업 창에 띄운다.
- **설정 페이지**: `options_ui`나 `options_page`를 탭으로 연다.
- **호환층** (`src-tauri/src/ext_compat.rs`, `src-tauri/ext-compat/`): WebView2에 없는 것을 채운다. 설치할 때와 시작할 때 확장 폴더의 `tbs-compat\`에 파일을 넣고 매니페스트와 HTML을 고친다. 크롬은 `_`로 시작하는 파일·폴더 이름을 거부하므로 이 이름을 쓴다.
  - **지금 탭**: WebView2는 웹뷰마다 "창 하나에 탭 하나"로 보여서, 팝업이 "지금 창의 활성 탭"을 물으면 팝업 자신이 나온다. 확장 HTML에 넣은 `page.js`가 그런 물음을 받아, TB's Browser가 지금 보여 주는 탭(주소와 제목으로 찾은 실제 탭)을 돌려준다. 확장에 그 주소를 볼 권한(`tabs` 또는 그 사이트 권한)이 있을 때만 알려 준다.
  - **새 탭 열기**: `chrome.tabs.create`와 `chrome.runtime.openOptionsPage`는 WebView2에서 아무 일도 하지 않는다. TB's Browser의 새 탭으로 연다. 웹 주소와 그 확장 자신의 페이지만 연다.
  - **오른쪽 클릭 메뉴**: 서비스 워커 앞에 끼운 `sw-shim.js`가 `chrome.contextMenus`로 만든 항목을 확장 저장소에 적는다. 확장마다 보이지 않는 브리지 페이지(`tbs-compat/bridge.html`)를 띄워 그 목록을 받고, 페이지의 오른쪽 클릭 메뉴(WebView2 `ContextMenuRequested`)에 넣는다. 한 확장의 항목이 여럿이면 확장 이름 아래로 묶는다. 누르면 브리지를 거쳐 확장의 `onClicked` 처리기를 부른다.
  - 호환층을 넣기 전에 설치한 확장은 시작할 때 고친다. 다만 메뉴 항목은 보통 확장을 설치할 때(`onInstalled`) 만들어지므로, 그런 확장은 지우고 다시 설치해야 메뉴가 보인다.
- **안 되는 것**: 네트워크 차단 규칙(`declarativeNetRequest`), 위에 적지 않은 창·탭 API(`chrome.tabs.update`, `chrome.windows.create` 등), 권한을 나중에 묻는 `chrome.permissions.request`. 확장 패널에 "일부 기능은 동작하지 않을 수 있습니다"라고 적는다.
- **확장 페이지를 연 탭**: 확장을 끄거나 업데이트하면 WebView2가 그 탭을 자기 빈 페이지로 보낸다. 확장이 켜져 있으면 그 페이지를 다시 열고, 꺼져 있으면 주소를 남긴 채 기다렸다가 다시 켤 때 연다.
- **하지 않는 것**: 크롬 웹 스토어 설치, 확장 자동 업데이트. 새 버전은 사용자가 zip을 다시 넣는다.
- **보안**: 확장 페이지도 앱 명령을 부를 수 없다. 확장은 콘텐츠 웹뷰 쪽에 속한다.
- **배포**: 크롬 확장은 앱이나 스크립트 저장소에 넣어 배포하지 않는다. 사용자가 받은 것을 직접 설치한다(라이선스가 제각각이다).

### 6.7 광고 차단 (내장)

확장의 네트워크 차단이 동작하지 않으므로 브라우저가 직접 한다.

- **엔진**: Brave의 `adblock-rust` 크레이트(MPL-2.0). 기본 목록은 EasyList, EasyPrivacy, List-KR이다. 하루에 한 번 갱신한다. 받은 목록은 `adblock\`에 둔다.
- **네트워크 차단**: 모든 요청에 `WebResourceRequested` 필터를 걸고, 막을 요청에는 빈 응답을 돌려준다.
- **화면 숨기기**: 사이트별 숨김 규칙을 콘텐츠 스크립트로 넣는다.
- **사이트별 끄기**: 주소창의 방패 버튼으로 한다. 이 페이지에서 막은 개수를 보여 주고, 사이트별로 끌 수 있다. 끈 사이트 목록은 `settings.json`에 둔다.
- **한계**:
  - 서비스 워커를 거치는 요청은 가로채지 못한다(0단계 9번).
  - 모든 요청이 호스트를 거친다. 10단계를 시작할 때 로딩 시간을 먼저 재고, 많이 느려지면 방식을 다시 정한다.

### 6.8 스크립트 저장소

사이트 스크립트를 나누고 받는 곳이다.

- **저장소**: 공개 GitHub 저장소 하나(`tbvwv123/TBs-Browser-scripts`). 스크립트 폴더들과 목록 파일 `index.json`이 있다.
- **찾아보기**: 확장 패널에서 연다. 목록을 보여 주고, 설치 전에 적용 사이트와 권한을 보여 주고 묻는다. 설치하면 zip을 받아 `scripts\`에 푼다.
- **업데이트**: 하루에 한 번 `index.json`의 버전과 비교한다. 새 버전이 있으면 확장 패널에 "업데이트"를 띄운다. 권한이 늘었으면 다시 묻는다.
- **만드는 법**: `docs/scripts.md`에 `script.json` 항목, `tbs.*` 부탁, 예시를 적는다.

## 7. 메모리 관리

메모리는 안 보는 탭을 단계적으로 재우고 버리는 정책으로 줄인다. 탭 하나가 쓰는 메모리는 Edge와 같으므로, 열려 있는 탭 수가 아니라 깨어 있는 탭 수를 줄이는 것이 목표다.

| 상태 | 들어가는 조건 (기본값) | 호스트가 하는 일 | 다시 볼 때 |
| --- | --- | --- | --- |
| 활성 | 지금 보는 탭 | 웹뷰를 보이게 둔다 | — |
| 백그라운드 | 다른 탭으로 넘어간 직후 | 웹뷰를 숨기고 메모리 목표 수준을 낮춘다(`MemoryUsageTargetLevel` = Low) | 즉시. 목표 수준을 Normal로 되돌린다 |
| 재움 | 안 본 지 5분 | `TrySuspend`로 렌더러를 멈춘다. 스크립트가 정지한다 | `Resume`. 페이지 상태가 그대로다 |
| 버림 | 안 본 지 30분, 또는 깨어 있는 탭이 12개를 넘을 때 가장 오래된 것부터 | 웹뷰를 닫는다. 주소·제목·파비콘만 남긴다 | 새 웹뷰로 다시 로드한다. 입력하던 내용은 사라진다 |

시간과 개수는 제안값이고 설정에서 바꿀 수 있게 한다.

다음 탭은 재우거나 버리지 않는다.

- 소리를 재생 중인 탭
- 다운로드나 업로드가 진행 중인 탭
- 전체 화면 중인 탭
- 사용자가 "항상 유지"로 표시한 탭(탭 오른쪽 클릭 메뉴)

구현 규칙은 다음과 같다.

- 모든 콘텐츠 웹뷰는 WebView2 환경 하나를 같이 쓴다.
- `TrySuspend`는 웹뷰를 숨긴 뒤에 부른다. 보이는 웹뷰에서는 바로 실패한다. 숨긴 뒤에도 실패할 수 있는 시도로 다룬다. 결과를 확인해 실패하면 다음 주기에 다시 시도한다.
- 메모리 목표 수준 낮추기와 `TrySuspend`를 한 탭에 섞어 쓰지 않는다. 재울 때는 `TrySuspend`가 수준을 알아서 낮춘다.
- 웹뷰를 닫기 전에 걸어둔 이벤트 처리기를 모두 떼다.
- 사이드바에서는 재운 탭과 버린 탭을 다르게 표시하지 않는다.

효과는 숫자로 확인한다. 탭 30개를 연 직후와 30분 뒤에, 이 브라우저에 속한 모든 프로세스의 메모리 합계를 기록한다. 같은 탭을 Edge에서 연 값과 나란히 적는다.

0단계에서 재 본 값은 두 가지다. 유튜브 탭 하나를 재우면 렌더러 메모리가 241MB에서 128MB로 줄었다. 탭을 버린 뒤 렌더러 메모리는 20\~30초 뒤에 풀렸다. 측정은 그만큼 기다린 뒤에 한다.

## 8. 데이터 저장

모든 데이터는 `%LOCALAPPDATA%\TBs Browser\` 아래 한 폴더에 둔다. 이 폴더를 통째로 복사하면 백업이 된다.

| 경로 | 내용 | 형식 |
| --- | --- | --- |
| `webview\` | 쿠키, 캐시, 로그인 정보. WebView2 사용자 데이터 폴더 | WebView2가 관리 |
| `state\session.json` | 탭, 그룹, 선택된 탭, 닫은 탭 목록, 사이드바 접힘 상태 | JSON |
| `state\bookmarks.json` | 북마크 트리, 폴더 접힘 상태 | JSON |
| `state\settings.json` | 설정값, 사이트별 권한 | JSON |
| `state\history.sqlite` | 방문 기록, 다운로드 기록 | SQLite |
| `scripts\<id>\` | 사이트 스크립트 (6장). 저장 공간은 그 안의 `storage.json` | 폴더 |
| `extensions\<id>\` | 설치한 크롬 확장 (6.6) | 폴더 |
| `adblock\` | 광고 차단 목록 (6.7) | 목록 원본 |
| `logs\` | 오류 로그 `tbs.log` | 글자 |

저장 규칙은 다음과 같다.

- JSON 파일은 임시 파일에 쓴 뒤 이름을 바꿔 덮어쓴다. 쓰다가 꺼져도 기존 파일이 깨지지 않는다.
- 모든 JSON 파일 맨 위에 `"version"` 항목을 둔다. 형식이 바뀌면 읽을 때 옛 형식을 변환한다.
- 세션은 변경 뒤 1초 동안 추가 변경이 없을 때 저장한다. 종료할 때 한 번 더 저장한다.
- 파일을 읽지 못하면 `.bak`으로 이름을 바꿔 남기고 빈 상태로 시작한다. 조용히 지우지 않는다.

북마크 파일의 모양은 다음과 같다. 세션 파일도 같은 방식으로 탭과 그룹을 담는다.

```json
{
  "version": 1,
  "collapsed": false,
  "items": [
    { "type": "link", "id": "b1", "title": "메일", "url": "https://mail.example.com/" },
    { "type": "folder", "id": "f1", "title": "업무 도구", "open": true, "items": [
      { "type": "link", "id": "b2", "title": "문서", "url": "https://docs.example.com/" }
    ] }
  ]
}
```

## 9. 구현 단계

아래 순서대로 한 단계씩 만들고, 각 단계의 시험을 사용자가 직접 확인한 뒤 다음으로 넘어간다.

| 단계 | 만드는 것 | 사용자가 해 볼 시험 |
| --- | --- | --- |
| 0. 기술 검증 | 빈 창에 UI 웹뷰 하나와 콘텐츠 웹뷰 두 개를 띄운다. 10장의 항목을 하나씩 시험하고 결과를 `docs/S0-results.md`에 적는다 | 두 사이트가 번갈아 보인다. 결과 문서에 항목마다 "됨 / 안 됨 / 대안"이 적혀 있다 |
| 1. 탭과 이동 | 탭 만들기·닫기·전환, 주소 입력, 뒤로·앞으로·새로고침, 제목과 파비콘 반영. UI는 꾀미지 않은 최소 모양 | 탭 5개를 열고 오가며 검색과 로그인이 된다 |
| 2. 창 틀과 기본 UI | 제목 표시줄 없는 창, 상단 툴바, 사이드바 탭 목록을 시안 F대로. 디자인 값은 `tokens.css` 한 파일에 | 시안 F와 나란히 놓고 비교한다. 창 이동, 크기 조절, 최대화가 된다 |
| 3. 북마크와 스크롤 | 북마크 트리, 추가·삭제·폴더, 탭과 합쳐진 스크롤, 붙는 머리줄, 스크롤 막대, 탭 그룹, 탭 검색 | 북마크 20개와 탭 30개에서 스크롤이 시안대로 동작한다 |
| 4. 저장 | 세션 복원, 방문 기록, 다운로드, 설정, 점 3개 메뉴, 단축키 | 꺼다 켜도 탭과 북마크가 그대로다. 파일을 받으면 진행 고리가 보인다 |
| 5. 사이트 스크립트 | 6장 전체와 관리 화면 | 6.5의 두 스크립트가 동작한다 |
| 6. 메모리 관리 | 7장의 상태 전환과 예외 | 7장의 측정을 하고 숫자를 기록한다. 음악을 튼 탭은 30분 뒤에도 재생된다 |
| 7. 나머지 화면 | 새 탭 화면(I·J), 접힌 상태(H), 다크 테마(G), 전체 화면, 권한 요청 | 시안 G·H·I·J와 비교한다. 유튜브 전체 화면이 된다 |
| 8. 마무리와 전달 | 설치 파일, 자동 업데이트(5.7), WebView2 런타임이 없을 때의 설치 처리, 오류 로그 파일 | 다른 PC에 설치해 처음부터 써 본다. 새 버전을 올리면 그 PC에서 업데이트가 설치된다 |
| 9. 크롬 확장 | 6.6 전체: 설치·켜기·지우기, 아이콘·팝업·설정 페이지 | DCRefresher Reborn zip을 설치해 디시에서 쓴다. 팝업과 설정 페이지가 열린다 |
| 10. 광고 차단 | 6.7. 먼저 로딩 시간을 잰다 | 광고가 많은 사이트에서 광고가 사라지고 로딩이 크게 느려지지 않는다. 사이트별로 끌 수 있다 |
| 11. 사이트 스크립트 v2 | 6.1·6.3의 새 항목과 권한, 설정 화면, 아이콘, 6.9의 1·2·4 | PiP 단축키, 제스처로 탭 닫기·되살리기, 유튜브 채널 차단이 된다 |
| 12. 스크립트 저장소 | 6.8 | 저장소에 올린 스크립트를 찾아 설치하고, 새 버전이 업데이트된다 |

0단계는 2026-11-10에 끝났다. 그 결과로 2장, 3장, 6장, 7장, 10장을 고쳤다. 8단계까지는 2026-11-11에 끝났다. 같은 날 확장 생태계(6.6~6.9)를 더하기로 하고 9~12단계를 덧붙였다. 다음은 9단계다.

## 10. 확인이 필요한 것

0단계에서 아래 13개 항목을 시험했고 12개가 됐다. 9번은 일부만 돼서 대안을 함께 쓴다(6.2). 항목별 결과는 `docs/S0-results.md`에 있고, 표의 "안 되면" 열은 계획 당시에 적은 대안이다.

| 번호 | 확인할 것 | 안 되면 |
| --- | --- | --- |
| 1 | Tauri의 `unstable` 자식 웹뷰로 UI 웹뷰 위에 콘텐츠 웹뷰 여러 개를 놓고, 위치·크기·보이기·숨기기를 바꿀 수 있는지 | `wry` + `tao` 직접 사용, 또는 `webview2-com`으로 직접 제어 |
| 2 | Tauri 웹뷰에서 네이티브 WebView2 객체를 얻어 `TrySuspend`, `AddScriptToExecuteOnDocumentCreated`, `WebResourceRequested`, `CapturePreview`를 부를 수 있는지 | 1번과 같은 대안 |
| 3 | 모든 웹뷰가 환경 하나와 사용자 데이터 폴더 하나를 같이 쓰는지. 한 탭에서 로그인하면 다른 탭에도 로그인되어 있는지 | 웹뷰를 만드는 방식을 바꾼다 |
| 4 | 페이지 카드의 12px 둥근 모서리를 낼 수 있는지(창 영역 잘라내기, 비주얼 호스팅) | 모서리를 각지게 하고 사용자에게 알린다 |
| 5 | 주소창 자동완성, 접힌 상태의 북마크 목록 같은 팝업을 콘텐츠 웹뷰 위에 띄울 수 있는지 | 팝업이 뜰 동안 콘텐츠 웹뷰를 줄이거나, 팝업을 별도 창으로 띄운다 |
| 6 | 제목 표시줄 없는 창에서 드래그 이동, 가장자리 크기 조절, 더블클릭 최대화, 스냅 레이아웃이 되는지 | 안 되는 동작을 적어 사용자에게 묻는다 |
| 7 | 포커스가 웹 페이지 안에 있을 때 Ctrl+T 같은 단축키를 호스트가 받을 수 있는지 | WebView2의 단축키 이벤트를 직접 처리한다 |
| 8 | `TrySuspend`가 성공하는 조건(웹뷰를 숨겨야 하는지)과 실제로 줄어드는 메모리 | 재우기 단계를 빼고 버리기만 쓴다 |
| 9 | 리소스 바꿔치기가 캐시나 서비스 워커를 쓰는 사이트에서도 적용되는지 | 스타일 덮어쓰기 방식으로 한다 |
| 10 | 콘텐츠 웹뷰의 웹 페이지가 앱 명령을 부를 수 없는지 | 막힐 때까지 다음 단계로 가지 않는다 |
| 11 | 비밀번호 저장과 자동 입력을 WebView2 설정으로 켤 수 있는지 | 기능에서 빼고 사용자에게 알린다 |
| 12 | 넷플릭스 같은 DRM 영상이 재생되는지 | 사용자에게 알린다 |
| 13 | 압축 해제 확장 불러오기가 되는지 (우선순위 낮음) | 6.6을 만들지 않는다 |

2026-11-11에 확장 생태계를 위해 더 시험했다(`docs/extensions-plan.md` 1장). 페이지의 영상 PiP, 크롬 확장의 서비스 워커·저장소·확장 페이지·콘텐츠 스크립트는 됐다. 확장의 `declarativeNetRequest` 차단은 안 됐다.

아직 확인하지 못한 것은 다음과 같다.

- 화면 배율 125%·150%에서의 모서리 영역, 스냅 레이아웃용 자식 창 위치, 페이지 카드의 1px 어긋남. 2단계에서 창 틀을 만들 때 가장 먼저 확인한다.
- 메인 창을 옮길 때의 팝업 창 처리.
- `withGlobalTauri`를 끈 뒤 콘텐츠 페이지에 남는 Tauri 객체.
- DRM 영상이 실제 화면에 보이는지. Spotify 웹 플레이어로 확인할 예정이다.
- 체스닷컴의 실제 기물 바꿔치기. 5단계에서 확인한다.
- 자동 업데이트. 서명한 새 버전을 올렸을 때 설치된 앱이 받아 설치하는지 8단계에서 확인한다.

문서에서 확인한 사실은 다음 두 가지다. Tauri에서 한 창에 자식 웹뷰를 만드는 기능은 `tauri` 크레이트의 `unstable` 기능을 켜야 한다. WebView2 문서는 탭 인터페이스에서 환경 하나를 같이 쓰라고 권하고, `TrySuspend`와 메모리 목표 수준 낮추기를 "최선을 다하는 시도"로 설명한다.

## 11. 작업 규칙

Claude Code는 아래 규칙을 따라 진행한다.

1. **0단계가 먼저다.** 10장의 항목을 시험하고 결과를 적기 전에는 본 기능을 만들지 않는다. 시험하지 않은 것을 된다고 말하지 않는다.
2. **단계마다 멈춘다.** 한 단계가 끝나면 9장의 시험을 사용자에게 건네고, 사용자가 확인한 뒤 다음 단계로 간다.
3. **시안이 기준이다.** 색과 치수는 4장과 `design/`의 시안 파일을 따르고, `tokens.css` 한 파일에만 적는다. 시안과 다르게 만들어야 하면 먼저 묻는다.
4. **범위를 늘리지 않는다.** 1장의 "하지 않는 것"과 5장에 없는 기능은 제안만 하고 만들지 않는다.
5. **보안 경계를 지킨다.** 콘텐츠 웹뷰에 앱 명령을 노출하지 않고, 웹 페이지에서 온 메시지는 모두 의심한다(3장, 6.3).
6. **버전을 고정한다.** `unstable` 기능을 쓰므로 Tauri와 관련 크레이트 버전을 정확히 고정하고, 올릴 때는 0단계 시험을 다시 돌린다.
7. **사용자 데이터를 조용히 지우지 않는다.** 저장 형식을 바꾸면 변환 코드를 함께 넣는다(8장).
8. **화면의 글은 한국어로 쓴다.** 오류 문구는 원인과 다음에 할 일을 같이 적는다.
9. **보고는 짧게 한다.** 바뀐 것, 사용자가 해 볼 시험, 남은 문제 세 가지를 적는다.
